# Короткий отчёт

## Что сделано

Сделан backend-first API для lead-capture модуля: создание заявки, просмотр
заявок, SQLite-хранение, валидация и README с проверкой через curl/Swagger.

## Что не успел / не делал намеренно

Не добавлял frontend, авторизацию и внешние интеграции. Для этого задания важнее
показать рабочий API и понятную проверку результата.

## Риски

- `GET /leads/` открыт без авторизации.
- SQLite подходит для прототипа, но под production лучше PostgreSQL.
- Телефон валидируется минимально.
- Нет rate limit и антиспам-защиты.

## Как проверял

- Создание валидной заявки через curl.
- Проверка списка заявок через `GET /leads/`.
- Проверка ошибок при отсутствии email/phone.
- Проверка ошибки при `consent=false`.
- Проверка `/docs` и `/health`.

## Сколько времени заняло

Около 2–3 часов.

## AI-гигиена

AI использовался для ускорения написания каркаса и README. Структура и решения
осознанно упрощены под задачу: FastAPI, async SQLAlchemy, SQLite, Pydantic.
